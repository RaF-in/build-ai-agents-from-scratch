Comprehensive Test Plan — Build Your Own AI Agent

Pre–go-live functional verification of every shipped capability, run on both the CLI and the Telegram surface, with behavioral pass/fail criteria and a map to the existing automated suite.

Hybrid: manual E2E + automated coverage map CLI & Telegram Happy path + key failures Behavioral assertions Dogfooding: code work + deep research

How to use this plan

Each functionality has its own section. Every test case states an Action (the exact prompt to type or command to run) followed by the Expected (behavioral) result. Because the agent is LLM-driven and non-deterministic, expected output is phrased as observable behavior — which tool is called, whether the error flag is set, whether a file/artifact/DB-row/trace-span is produced — never exact wording. A test passes if the behavior holds, regardless of phrasing.

Each case also carries a coverage line:

  • Covered by: an existing automated test in testing_files/ exercises the same unit — run it for a fast, repeatable signal.
  • Gap: no automated test exists; this is a manual-only check and a candidate to harden into a new test_*.py.

Scope & decisions

Confirmed with you
  • Format: hybrid — manual end-to-end cases + a pointer to the covering testing_files/ test + explicit gaps to automate later.
  • Surfaces: every functionality tested on CLI and Telegram; CLI-only where the interface is inherently CLI (e.g. interactive /new confirm).
  • Depth: happy path + the key failures that would break a live demo, with a day-to-day dogfooding lens (real code work + deep research).
  • Expected output: behavioral assertions only.
  • Deep research: exercised on both technical and non-technical topics.
  • Provider: mixed per feature (recommended provider noted per section) to control cost on the fan-out-heavy paths.
Out of scope (your call)
  • Bot/abuse security hardening — the public Telegram bot exposes Bash/Write/Edit with host FS access; you are handling deployment security separately.
  • Go-live / deployment readiness — hosting, webhook registration, secrets management are owned elsewhere.
  • Article-writer capability — not fully developed; intentionally untested here.

1. Agent loop

The turn loop in agent.py: send a message → LLM streams a reply → tool calls are dispatched → results fed back → loop until the model stops calling tools (completion gate). Includes the tool-call guardrail (after many tool calls, the agent is told to stop and summarize) and the idle-loop safety bound.

Files: agent.py (run_to_completion, completion gate, TOOL_CALL_GUARDRAIL_INSTRUCTION). Provider: LM Studio.

7. Cron jobs

The CronService loop (10s tick) enqueues due jobs; main.py delivers them back through a full agent.request on the right channel. Schedule forms: in:5m (one-shot), interval:3600 (recurring secs), or a 5-field cron expression.
